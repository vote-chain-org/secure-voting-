# Secure Voting System — Full Integration Implementation Plan

## Background

The project consists of three major subsystems that need to be integrated into a single functional distributed voting system:

1. **Spring Boot Backend** (`git_cloned/backend/`) — Existing auth + user + vote management with JWT, PostgreSQL
2. **Hyperledger Fabric Blockchain** (`sample_hyperledger_stuff/`) — Java-based chaincode + client app for 3-booth voting network
3. **ML Fingerprint Verification** (`git_cloned/backend-ml/`) — Python FastAPI service with liveness detection and minutiae matching
4. **SecuGen Fingerprint SDK** (`sample_fingerprint_stuff/`) — USB scanner reference for capturing PNG fingerprints
5. **React Frontend** (`git_cloned/frontend/`) — Existing UI with election pages, auth, profile

### Current State Summary

| Component | State | Key Issues |
|-----------|-------|------------|
| Backend | Partially functional | No fingerprint, blockchain, or ML integration. No admin endpoints. |
| Frontend | Functional UI | Fingerprint modal exists but calls ML directly from browser. No admin dashboard. |
| Blockchain | Reference only | Standalone Javalin/Gradle app (App.java), not integrated. Must be converted to Maven. |
| ML Service | Functional standalone | FastAPI service with liveness + minutiae matching. Works independently. |
| Fingerprint SDK | Reference only | SecuGen SDK code samples for Java. Not integrated. |

## User Review Required

> [!IMPORTANT]
> **Corrected Architecture**: The Spring Boot server does **NOT** interact with Hyperledger Fabric directly. Each booth is an independent Java application that holds its own Fabric identity and submits transactions. The server acts only as a coordinator/router, forwarding vote requests to the appropriate booth.

> [!IMPORTANT]
> **ML Service is Centralized on the Server Machine**: The ML FastAPI service runs **only on the server machine** (alongside Fabric network and Spring Boot). It is NOT deployed per booth. All booth applications call it over the network via `http://<SERVER_IP>:8000`. This ensures a single point of ML model management and avoids duplicating GPU/model resources.

> [!IMPORTANT]
> **Fingerprint Capture on Booth Hardware**: SecuGen SDK requires Windows-native JNI. Each booth app runs natively on a Windows laptop (as a JAR), NOT inside Docker. The booth app captures the fingerprint directly via SecuGen SDK on the host OS, converts it to PNG, passes it to the ML service, and then submits the vote to the blockchain.

> [!WARNING]
> **Hyperledger Fabric Network**: The blockchain network (orderer, peers, CouchDB) runs in Docker containers **on the server machine**. The booth Java apps connect to the network from their Windows laptops over the network using `<SERVER_IP>:<port>` — **NOT `localhost`**, since the booths are on separate machines. Docker is for infrastructure only — booth apps and fingerprint capture run natively on Windows.

> [!WARNING]
> **No Gradle**: All Java projects (booth apps, chaincode) must be Maven-based. No Gradle build system is used anywhere.

## Vote Flow

```
  User at Booth Machine (Windows Laptop)
           │
           │ 1. Clicks "Vote" on frontend
           ▼
  ┌─────────────────┐
  │ React Frontend  │  POST /api/votes/cast {voterId, candidateId, boothId}
  └────────┬────────┘
           │
           ▼
  ┌─────────────────┐
  │ Spring Boot     │  Routes to booth via BoothRoutingService
  │ Server (8080)   │  POST http://booth{N}-ip:900{N}/castVote
  └────────┬────────┘
           │ HTTP
           ▼
  ┌─────────────────────────────────────────────────┐
  │ BOOTH APP (Java JAR, running on Windows laptop) │
  │                                                  │
  │  Step 1: SecuGen SDK → captures fingerprint PNG  │
  │                                                  │
  │  Step 2: POST http://<SERVER_IP>:8000/verify      │
  │          → sends PNG + voterId                    │
  │          ← receives {verified: true/false}        │
  │                                                  │
  │  if NOT verified → return error to server         │
  │                                                  │
  │  Step 3: Fabric Gateway SDK                      │
  │          → castVerifiedVote(voterID, candidateID) │
  │          ← tx hash                                │
  │                                                  │
  │  Step 4: Return {status, txHash} to server        │
  └────────┬────────────────────────────────────────┘
           │
           ▼
  ┌─────────────────┐
  │ Spring Boot     │  Saves Vote to PostgreSQL (txHash, metadata)
  │ Server          │  Returns success to frontend
  └────────┬────────┘
           │
           ▼
  ┌─────────────────┐
  │ React Frontend  │  Shows "Vote Recorded" with tx hash
  └─────────────────┘
```

- ✅ Unique MSP identity
- ✅ Unique certificate and key pair
- ✅ Unique peer connection (port-based)
- ✅ Runs natively on its own Windows laptop
- ✅ SecuGen USB scanner physically attached
- ✅ Connects to centralized ML service on server via `http://<SERVER_IP>:8000`
- ✅ Connects to Fabric peer on server via `<SERVER_IP>:<port>` (NOT `localhost`)
